# Paint Squad art

Art ported from the owner's own sibling project Paint Squad Wars (`~/TactileWars`, project-owned original art generated by its Blender and editor scripts; fonts are third party SIL OFL 1.1). Everything lives under `Assets/Rebuild/PaintSquad/`. No Paint Squad Wars C# scripts are copied.

## Rebuild

`python3 -I Tools/Rebuild/port_paint_squad_art.py [path/to/TactileWars]` copies every asset below with its `.meta` (import settings, FBX material remaps and GUIDs are kept, so references between the copied assets resolve) and rebuilds the three VFX prefabs. It only reads the source project. Run it with the Team5 editor closed or let the editor reimport afterwards. `PaintSquadAssetTests` (EditMode) checks the result.

## VFX notes

The source prefabs carried `PooledVfx` / `PaintProjectile`. Those components are removed; the particle systems now play on awake and do not loop. Values the removed scripts held, for whoever drives the effects in Team5:

- Muzzle flash: lifetime 0.15 s, one system (`Flash`), not tinted.
- Hit splash: lifetime 0.5 s, systems `Droplets` (tinted with the shooter colour) and `Flash` (not tinted).
- Paintball: a camera-facing `M_Quad` with `M_Team_Red_Dot`; the source script moved it and billboarded it.

In Paint Squad Wars the unit prefab scales the model by 0.9 and places a `BlobShadow` quad (`M_Quad`, `M_BlobShadow`) at y 0.015, scale 0.945, lying flat.

Prefab layout: root (foot point) with `UnitView` and `PaintSquadUnitAnimation`; child `Model` (the unpacked FBX with its Animator, role materials and gear; rotated for facing); child `Blob Shadow` (`M_Quad` with `M_BlobShadow`, 0.8 wide, y 0.015). No colliders, model shadows off. Scale: each base model gets one shared scale (Soldier 0.933, height about 0.95; SoldierHeavy 0.989, height 1.0; Hero 0.803, height about 1.24); a role whose gear would overhang shrinks so the model and gear stay within 0.87 across the rest, Idle and Run poses (Sniper 0.933, Demolisher 0.907, Warcaller 0.908, Frostweaver 0.864). For comparison the Catgirl prefabs are about 1.47 tall and 0.74 wide.

`PaintSquadUnitAnimation` is bound by `BattlePresentation.CreateView` like `HaonUnitAnimation` and `FWUnitVisual`. It only observes the simulation: Speed 0/1 (Idle/Run blend) from route progress or continuous movement, Shoot plus `PaintSquadMuzzleFlash` when the unit's attack cooldown re-arms (and on its legendary skill), Hit plus `PaintSquadHitSplash` on `UnitDamaged`, Cheer when the battle is won, Idle with the Animator stopped while paused. Units turn toward their movement, and toward the tower they shot at for a moment after firing. On death `BattlePresentation` calls `LeaveFallenBody`, which moves the model and shadow into a short-lived `PaintSquad Fallen <id>` object that plays Die, then the view is destroyed as before.

No scene uses the catalog yet; character selection (Task 3) chooses it at runtime. Tests: `PaintSquadRoleVisualTests` (EditMode), `PaintSquadUnitPlayModeTests` (PlayMode).

## Character select (Task 3)

Flow: StartGame, **Start Game** opens the "Choose your squad" overlay (`LegacyUI/CharacterSelectScreen.cs`, built at runtime with `LegacyUiKit`), a card tap stores the choice and calls `BattleSceneFlow.BeginRun()` (Level 1 as before). **Back** closes the overlay. The test title scene (`TestStartScene`) skips the overlay. Play Again returns to StartGame, so the screen is shown on every new run, with the stored set outlined as SELECTED.

- `Session/CharacterSetSelection.cs`: `CharacterSet { PaintSquad, Catgirl }` and a static API over PlayerPrefs key `Team5.CharacterSet` (values `PaintSquad`, `Catgirl`; missing or unknown values give the default `PaintSquad`). `Current`, `Set(set)`, `Parse`, `ToValue`.
- `Resources/CharacterSetCatalogs.asset` (`CharacterSetCatalogs`): per set the display name, tagline, role catalog (`PaintSquadAllRoles` or `CatgirlAllRoles`), Captain preview sprite and role portraits (Paint Squad only).
- Battle scenes: `BattlePresentation.EffectiveRoleVisuals` = `CharacterSetCatalogs.Resolve(roleVisuals)`, evaluated per spawned view. A scene whose serialized `roleVisuals` is one of the selectable catalogs (Level 1 to 7, TestLevel, `1.unity`) uses the selected set's catalog; a scene with no catalog or another catalog (Haon, FW and Catgirl test scenes) is untouched; if the lookup fails the serialized catalog is used.
- Scene-authored per-member overrides (`useTestUnitVisual`, `testVisualMemberId`, `additionalTestVisuals`; Level 1 forces member 110 to `CatgirlCaptain`, `1.unity` forces 111 to 114) only apply while the effective catalog is the scene's own, so with Paint Squad selected the Paint Squad Captain is used and with Catgirl selected nothing changes. A runtime `SetTestVisual` call (`FWVisualTestSwitch`) still always applies.
- Unit icons: `LegacyUnitIconUI.SetType` shows the selected set's role portrait when it has one, so every surface built on it follows the choice (battle HUD squad button, unit inspection, warehouse cards and drag ghost, formation grid and editor, summon claim cards and unit intro popup, legendary skill panel, Captain guide). Catgirl has no portraits and keeps the block icons exactly as before. The next level preview has no unit icons.
- Level 1 tutorial: step 1 reads "The gold spiked hero is your Captain." when the Captain view is a Paint Squad unit; the Catgirl and block texts are unchanged.

Menu **Team5/Rebuild/Paint Squad/Build character set catalogs** (`Editor/PaintSquadCharacterSetBuilder.cs`) renders the ten role portraits (`PaintSquad/Portraits/PaintSquad<Role>Portrait.png`, 256 px, Idle pose, front three-quarter) and the two Captain previews (`PaintSquadSelectPreviewPaintSquad.png`, `PaintSquadSelectPreviewCatgirl.png`, 512 px), imports them as sprites and rewrites `Resources/CharacterSetCatalogs.asset`. Each image is rendered over black and over white and the alpha is recovered from the difference, so the background is transparent. It needs a graphics device: run it from the editor or with `-batchmode -executeMethod Team5.Rebuild.Editor.PaintSquadCharacterSetBuilder.Build -quit`, without `-nographics`.

Tests: `CharacterSetSelectionTests` (EditMode: PlayerPrefs default, round trip, unknown values, catalog asset, `Resolve`, `run_start` payload) and `CharacterSetPlayModeTests` (Level 1 with each set including the overridden Captain, select screen tap). PlayMode tests for Catgirl-authored scenes pin the Catgirl set with `CharacterSetPrefsScope` and restore the stored value afterwards.

## UI look (Task 4)

Every Team5 screen now uses the Paint Squad Wars UI language: beige hex paper backgrounds, cream cards with a rim and a thicker bottom edge, chunky rounded buttons whose face is a little glossy over a darker drop edge, title ribbons with folded tails, Lilita One headings with a dark outline, Fredoka body text, slate plates for the HUD and tutorial bars, and the ported icons (coin, heart, check, close, arrows).

- **Palette** (`LegacyUiKit`, taken from Paint Squad Wars' `UIColors`): Ink `#2A2D3A`, InkMuted `#7D8190`, Slate `#3A4052`, SlateLight `#535B70`, SlateDark `#262A36`, ButtonSlate `#4A5165`, Card `#FBF8F1`, CardInner `#EDE7DA`, CardRim `#CFC6B3`, CardLine `#DCD4C4`, Gold `#F6B12B` / `#C27A14`, Green `#76BD36` / `#4C8A1F`, Red `#E04A2F` / `#A02D1C`, Blue `#3E8EDB` / `#255E9F`, Grey `#B9BDC6` / `#868B97`, Paper `#CFC6A9`. The old names map onto it: `PanelColor` Slate, `PanelLineColor` SlateLight, `CellColor` SlateDark, `TextColor` white, `MutedColor` Grey, `HighlightColor` Gold, `NodeGreenColor` Green, `NodeBlueColor` Blue. Rarity colors (`LegacyUnitLooks.RarityColor`) are silver `#A9AEB9`, blue `#3E8EDB`, purple `#8F63B0`, gold `#F6B12B`.
- **Kit** (`LegacyUI/LegacyUiKit.cs`, public API unchanged and extended): `CreateText` picks Lilita One for bold text and Fredoka otherwise, drops faux bold, and gives light text the outline material (`StyleText`, `ApplyOutline`, `Outlined`); `Round` uses the skin's 9-slice `rounded32`; `MakeButton` turns rounded and round images into the chunky button sprites (`Chunky`, `RoundButton`); new helpers `CreateCard`, `CreateShadow`, `CreateRibbon`, `CreateBackdrop`, `CreatePill`, `CreateIcon`, `Panel`, `SkinButton`, `SkinSlider`. Without the skin asset it falls back to its procedural sprites and the TMP default font.
- **Scene-authored UI** (`LegacyUI/PaintSquadSceneSkin.cs`) is restyled at runtime by its existing owners, so no scene file changed: `LegacySceneMenu` (title and end screens: backdrop, outlined title, chunky buttons, the selected squad's Captain as mascot), `LegacyLevelSettlement` (ribbon heading, red for a win and slate for a loss, cream reward card), `LegacyUpgradeScene` (backdrop, cream storage and squad boards on the scene canvas, green Start Wave) and `LegacyBattleHud` (speed bar).
- **Skin asset**: `Resources/PaintSquadUiSkin.asset` (`PaintSquadUiSkin`) references the fonts, outline materials, shapes and icons. Menu **Team5/Rebuild/Paint Squad/Build UI skin** (`Editor/PaintSquadUiSkinBuilder.cs`, also `-batchmode -nographics -executeMethod Team5.Rebuild.Editor.PaintSquadUiSkinBuilder.Build -quit`) draws `PaintSquad/UI/Generated/` (`PaintSquadButton.png`, `PaintSquadButtonCircle.png`, `PaintSquadPanel.png`, `PaintSquadHexPaper.png`), bakes the fonts and rewrites the asset.
- **Fonts**: `Fredoka SDF` and `LilitaOne SDF` are static (printable ASCII plus en and em dash, middle dot, bullet, multiplication sign, ellipsis, degree sign and curly quotes), so play and tests no longer rewrite them. Their fallback is Team5's `LiberationSans SDF` (which keeps its own dynamic fallback), so any glyph the new fonts lack, including CJK text, still renders. Static font assets drop the runtime TTF reference and keep its GUID. Add characters by extending `PaintSquadUiSkinBuilder.Characters` and rerunning the builder; `PaintSquadUiSkinTests.EveryCharacterInUiStringsRenders` fails when UI code uses a character that neither font nor the fallback has.

### Screenshots

`PaintSquadScreenCapture` (runtime, `Scripts/Presentation/Minimal`) saves the current Play Mode frame with all overlay UI at any size, independent of the Game view: `PaintSquadScreenCapture.Capture("name", 1920, 1080)` (fire and forget) or `yield return PaintSquadScreenCapture.CaptureRoutine("name", 1920, 1080)` in a Play Mode test. Files go to `Logs/PaintSquadScreens/<name>.png` (gitignored). In the editor, use **Team5/Rebuild/Paint Squad/Capture Game View 1920x1080** or **960x600** during Play Mode.

`Tests/PlayMode/PaintSquadScreenTour.cs` is an explicit test that walks every screen with the Paint Squad set (title, select, Level 1 tutorial, Level 2 HUD with legendary skills and health bars, formation editor, squad inspection, skill tooltip, defeat card, settlement win and loss, first summon guide, summon offer, new unit popup, upgrade, unit details, dismiss confirm, next level preview, storage full, end) and captures each one:

```
PAINT_SQUAD_CAPTURE_PREFIX=task4 Unity -batchmode -projectPath ~/Team5 -runTests -testPlatform PlayMode \
  -testFilter Team5.Rebuild.Tests.PaintSquadScreenTour -testResults Logs/tour.xml
```

Run it without `-nographics`. Tests: `PaintSquadUiSkinTests` (EditMode: skin asset, sprite slices, static fonts with fallback, every UI string character renders, kit text and button styling, idempotent backdrop).

Note: `Tools/Rebuild/port_paint_squad_art.py` copies the source (dynamic) font assets back; rerun **Build UI skin** after it to make them static again.

## Level dressing (Task 5)

`Editor/PaintSquadLevelDressing.cs`, menu **Team5/Rebuild/Paint Squad/Dress levels** (batch: `-executeMethod Team5.Rebuild.Editor.PaintSquadLevelDressing.DressLevelsBatch`), rebuilds the 16 prop prefabs in `PaintSquad/Environment/` (`PaintSquadTree_A` ... `PaintSquadTent`, each the Task 1 model scaled to a fixed height with its ported materials, no colliders, Ignore Raycast layer, batching static, no shadow casting) and then dresses `Level1GridBattle` to `Level7GridBattle`:

- Everything goes under one scene root, `Paint Squad Dressing`. Rerunning deletes and rebuilds that root; the layout is seeded by the scene name, so it comes out the same each time.
- Ground: the existing `Decorative Border Tiles` (Levels 1 to 4). The Map Builder levels (5 to 7) have an empty border, so the tool lays four flat slabs with `DecorativeBorder.mat` around the grid, under the dressing root. No gameplay tile or material is changed.
- Only tiles visible to the battle camera are used. By ring distance from the grid: ring 1 small grass, flowers and pebbles (30 percent); ring 2 bushes, rocks, the odd crate or barrel (45 percent); ring 3 and beyond mostly pine trees, with bushes, big rocks, logs, fences and a rare tent (72 percent). Positions get a small jitter, a random yaw and a 0.85 to 1.15 scale.
- A prop is rejected if its bounds overlap any BattleCell (every BattleCell is gameplay), or if, seen from the battle camera, any of its corners lands on the playfield plus a 0.6 margin. A rejected prop is replaced by the next lower one (bush, rock, grass), so the near (camera) side only ever gets low props.

Test: `PaintSquadLevelDressingTests` (EditMode). Screenshots: `PaintSquadScreenTour.CaptureEveryLevel` (explicit Play Mode test) writes `<prefix>-level<N>.png` and `<prefix>-level<N>-overview.png`.

Note: Unity reserializes the level scenes on save (default values for newer fields). The committed scenes keep the original text for existing objects and only add the dressing objects.
